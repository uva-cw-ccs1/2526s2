# Computational Communication Science I (CCS1)

**University of Amsterdam, Department of Communication Science**

This repository holds teaching materials for CCS1: lecture notebooks, tutorial exercises, weekly practice sets with solutions, and the final exam. It also serves as the course syllabus. CCS1 is a course introducting Python to social science students. The course treats programming not as a set of commands to memorise, but as a way of understanding how a machine processes instructions. Students who finish the course should be able to read unfamiliar code and reason about what it can and cann do, which matters as much as being able to write code of their own.

## Learning objectives

By the end of the course, students can:

1. Work confidently in JupyterLab and explain how a notebook executes code, including the effect of execution order and kernel state.
2. Use Python's core data types (integer, float, string, boolean, list, dictionary) and choose an appropriate structure for a given problem.
3. Control the flow of a program using conditional branches and `for` loops.
4. Write their own functions, and explain why a function is preferable to repeating code.
5. Import and use external libraries, including `pandas` for reading and structuring data.
6. Produce basic visualisations of a dataset.
7. Read code they did not write, trace its execution by hand, and identify errors, including code that runs without raising an error but returns the wrong result.
8. Write readable code with meaningful comments.

## How a week works

Each week consists of one lecture and one tutorial. Tutorials combine up to four kinds of activity:

**Knowledge quiz.** A short check on the concepts from the preceding lecture, taken at the start of the tutorial.

**AI code review.** Students receive Python code generated by a large language model, printed on paper. Working with a pen and without a computer, interpreter, or any external source, they find and correct the mistakes. The point is to trace execution by reading, and in particular to distinguish code that fails loudly from code that runs cleanly and returns the wrong answer. Feedback on each review is given in a later tutorial.

**In-class assignment.** A longer graded problem completed during the tutorial.

**Coding exercise.** Guided practice on the week's material, worked through together.

## Weekly schedule

### Week 1: Data types
Navigating JupyterLab, the `print()` function, and the basic data types: integer, string, float, boolean, and lists.

- **Lecture:** Introduction to Python and JupyterLab notebooks, data types
- **Tutorial:** Knowledge quiz 1, AI code review 1, coding exercise
- **Reading:** Van Atteveldt, W., & Peng, T. Q. (2018). When communication meets computation: Opportunities, challenges, and pitfalls in computational communication science. *Communication Methods and Measures, 12*(2-3), 81-92.

### Week 2: Control flow and for loops
Controlling the flow of a program with `if` / `elif` / `else` branches and loops. `while` loops are mentioned briefly; the course then focuses exclusively on `for` loops.

- **Lecture:** Conditional statements, for loops
- **Tutorial:** Knowledge quiz 2, AI code review 2, coding exercise
- **Reading:** Van Atteveldt, W., Strycharz, J., Trilling, D., & Welbers, K. (2019). Toward open computational communication science: A practical road map for reusable data and code. *International Journal of Communication, 13*, 20-20.

### Week 3: Lists and dictionaries
Dictionaries, and further methods for modifying lists. For loops are revisited and combined with dictionaries.

- **Lecture:** Lists, dictionaries, for loops, recap
- **Tutorial:** In-class assignment 1, coding exercise, feedback on AI code review
- **From this week onward,** an anonymous feedback link is open on Canvas for the rest of the semester. Use it at any point. We read it regularly and change the course where we can.

### Week 4: Functions
Why functions are needed, and how to write your own.

- **Lecture:** Functions
- **Tutorial:** In-class assignment 2, coding exercise

### Week 5: Libraries and functions
Importing libraries. Functions are revisited in the context of libraries.

- **Lecture:** Libraries, calling functions from a library, recap
- **Tutorial:** Knowledge quiz 3, AI code review 3, coding exercise
- **Optional catch-up session** (online): a Q&A covering the first four weeks of the course.

### Week 6: pandas
The `pandas` library, reading data from files, and structuring data in a data frame in preparation for statistical analysis.

- **Lecture:** pandas, files, data frames
- **Tutorial:** In-class assignment 3, coding exercise, feedback on AI code review, writing neat code and commenting

### Week 7: Visualisation and summary
Visualising data using Python libraries, followed by a summary and recap of the course.

- **Lecture:** Visualisation, summary, Q&A
- **Tutorial:** Knowledge quiz 4, coding exercise, feedback on in-class assignment, Q&A
- **Optional catch-up session** (online): a Q&A covering the entire course.

### Week 8: Final exam
The exam follows the format of the in-class assignments but is more extensive. Students combine material from across the course to solve coding problems.

## Use of generative AI

Generative AI is now a default feature of most coding environments, students are already using it, and a prohibition would be neither enforceable nor instructive. **We will not police your use of AI in this course.**

What we will do instead is show you where it fails. The AI code reviews exist because generated code has a specific failure mode that is dangerous for a beginner: it often runs without raising an error and still returns the wrong answer. Code you did not write is also considerably harder to debug than code you did. Both of these are much easier to see on paper, with the interpreter out of reach.

The one thing worth saying plainly: if you let a model write your code all term, you will not be able to read the exam.

## Repository structure

```
week1/ ... week7/
    Lecture/          notebooks used during the lecture
    Tutorial/         in-class coding exercises
    practice.ipynb            self-paced exercises for that week
    practice_solutions.ipynb  worked solutions

exam/
    final_exam_CCS1.ipynb
```

Some tutorial notebooks come in `_STUDENT` and `_SOLUTIONS` pairs. Work through the student version first; the solutions are there to check against, not to read ahead.

**Most coding exercises can be solved in many different ways, and there is rarely a single correct solution.** If your code produces the right result by a different route than the solution notebook, your code is correct. Comparing the two routes is usually more instructive than either one alone.

Materials for a given week are added as the week approaches. If a folder looks incomplete, check back closer to the session.

## Getting set up

You will need Python and JupyterLab. The simplest route is to install the [Anaconda distribution](https://www.anaconda.com/download), which bundles both along with `pandas` and the plotting libraries used later in the course.

To use these materials, either clone the repository:

```bash
git clone https://github.com/uva-cw-ccs1/2526s2.git
```

or download individual `.ipynb` files from the web interface and open them in JupyterLab.

## Getting help

**Office hours** are held weekly by the course coordinator. **Optional catch-up sessions** run online in weeks 5 and 7 for anyone who wants to go back over earlier material. Tutorial time is also available after class for questions on the exercises.

From week 3, the **anonymous feedback link on Canvas** is open for the rest of the semester. It is genuinely read. Several changes to the course during the semester came directly from it.

If you are stuck, being stuck is not a sign that you cannot do this. Getting a long run of error messages is an ordinary part of programming, including for people who have been doing it for years. Ask early rather than late.
